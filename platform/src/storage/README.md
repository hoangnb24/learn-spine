# Storage v0 — #10

`createStorage(options?)` implements the normative `Storage` interface from model. Public functions always resolve `Result`, with `warnings: []` on success. It never changes an active session. `unpack` and `recover` hand back a fully validated defensive `ProjectBundle`; the session owner (#7) swaps only after success, and keeps immutable byte versions referenced by undo/checkpoints. `validateBundle(unknown, signal?)` is also exported, and is available on the instance, for #7's preparation boundary before import or replacing an image.

- `pack`: validates and snapshots JSON plus all bytes before asynchronous work, exports UTF-8 `project.json` and PNG files in a portable ZIP. No machine paths, editor state, history, or external fetches.
- `unpack`: validates ZIP paths, duplicate paths, CRC32, declared and streamed decompressed sizes; strict model `parse` rejects duplicate JSON keys, unsupported versions/capabilities and invalid semantics. PNG SHA-256, IHDR and actual decoder dimensions must match. Unsupported versions are rejected; v0 identity migration is a defensive copy and preserves projectId/revision. Source archive bytes are never mutated.
- `autosave`: snapshots first and commits project + bytes in one IndexedDB transaction. Success means transaction complete, not request queued. A stored equal or newer revision rejects with `REVISION_CONFLICT`, protecting against late completion and ambiguous same-revision content from another session. Callers should avoid repeating already saved revisions; this API does not silently replace equal revisions. Quota/I/O/transaction abort produces `STORAGE_FAILED`, explicit cancellation `CANCELLED`. Keep the UI unsaved on failure; export remains separate.
- `recover(projectId)`: loads the latest committed bundle or returns `null` when absent, revalidates it before returning. Corrupted local records return an error, never a partial project. It does not restore history/dedup or reset revision.

Limits follow semantics: 200 MiB uncompressed aggregate, 20 MiB per PNG, 256 assets, dimensions 16384, aggregate 64 million pixels. ZIP input is additionally bounded to 201 MiB for container overhead. STORE and raw DEFLATE work; exports use STORE (portable, PNG is already compressed). Single disk only; ZIP64, encryption, symlinks, non-manifest files, directory entries, preambles/gaps, and unsupported flags/methods are rejected. CRC and local/central headers are cross-checked; DEFLATE is streamed with an actual output budget before collecting chunks.

Browser defaults use `crypto.subtle`, `createImageBitmap`, `DecompressionStream('deflate-raw')`, IndexedDB. Non-browser hosts may inject `decodePng` **only with a real decoder**, and `indexedDB`; no fallback pretends header parsing is decoding. `databaseName` isolates stores for hosts/tests. Absence of a browser facility returns a structured failure. Database handles close after every operation and on versionchange.

Browser acceptance harness lives in `tests/storage/harness.html`; Playwright starts an isolated Vite server on 4181, uses real Chromium PNG creation/decoding and IndexedDB, then reloads the page. Failure tests inject quota exceptions and transaction aborts into the real browser store; they do not claim to physically exhaust a disk. Current UI integration is owned by #12/#13.
