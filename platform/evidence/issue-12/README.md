From `platform/`:

```sh
npm ci
```

Actual outcomes: typecheck passed; 61 unit tests passed; production build passed;
default browser suite passed (built shell/navigation/responsive, real storage and
editor integration); scoped editor suite passed. The build reports a >500 kB shared
renderer/storage chunk warning, with no build failure. Exact counts and head are
recorded in the PR after final verification.

The editor suite starts the actual Vite app on port **4182** to exercise its normal
module integration boundary. Default CI imports that suite automatically and also
checks the **built** editor/player entries on **4173**. Storage tests use **4181**.
No editor test globals are shipped to production. Source PNG art is generated by the
test in a real browser canvas (orange rectangle with teal end), so the tests need no
private art files or workspace paths. Renderer uses real WebGL and PNG decoding.

## What was observed

- New valid project → child bone → PNG import/attachment → Setup transform → animation
  and two rotation keys. Scrubbing from 0 to 0.5 changes actual canvas pixels; playback
  advances and pauses. Undo removes the second key; redo restores it.
- Empty numeric key and malformed ZIP/PNG show recoverable errors and leave the entire
  project unchanged. A subsequent valid exported package opens in Editor.
- A command dispatched through the same Session from outside React renames the selected
  bone; tree, inspector and canvas revision update. History and checkpoints restore.
- Save commits to real IndexedDB; reload followed by **Khôi phục bản lưu** preserves the
  full Project. The exported ZIP opens and plays in a **fresh browser context after the
  editor page is closed**, with no editor storage or globals in that context.
- Injected save failure leaves the UI unsaved and export available. Cancellation leaves
  committed project state unchanged. This simulates an I/O failure; it does not claim
  to have physically exhausted the disk.
- Late save/import completions are discarded after reopening the same project ID and
  revision into a new session. Identical already-saved package content is recognized
  only after validating the actual stored record; different content at equal revision
  remains a conflict and is never overwritten.
- Desktop and 390px layouts have no horizontal page overflow. Narrow property/timeline
  panels scroll. Browser-plugin inspection also created a project and bone through
  the visible UI and checked the resulting selection and real workspace screenshot.

## Manual walkthrough and integration

1. Run `npm run dev`, open `index.html`, click **Project mới**.
2. Name and add a bone. With it selected, choose **Nạp PNG**. Images attach centered
   at that bone. Use Setup position/rotation/scale to arrange each body part.
3. Add a movement (initially a two-second loop). Set time and key value, click **Đặt key**;
   repeat at another time. Use **Phát**, **Tạm dừng** and the time slider to inspect.
4. Use **Hoàn tác / Làm lại**, or create/restore a session checkpoint in **Lịch sử**.
5. **Lưu trình duyệt** (also automatic after edits), reload, then **Khôi phục bản lưu**.
6. **Tải gói project**, close Editor, open `player.html`, select that ZIP and play.

[Editor integration API and limitations](../../apps/editor/README.md) is the handoff
for #13/#14: use the existing `editorRuntime.session`, not a second live Project.
Current minimal controls offer Setup transforms, bone parent, image-to-bone assignment,
linear/stepped key insertion, playback, history and local/package storage. Full curve
editing, attachment pivot controls and richer animation settings remain outside this
minimal UI; the canonical core still preserves and plays imported supported data.
Camera fit samples the animation rather than proving all continuous extrema. Only
Chromium/macOS was exercised here; no Safari/Firefox or animation performance gate claim.
